\subsection{PUT and GET Operations}
\label{sec:operations}

% PUT Operation description
% - Discretize coordinates (raster projection)
% - Compute k hash positions using hashing trick
% - For each hash position, increment first non-maximal layer

\begin{algorithm}[ht]
\caption{PUT Operation}
\label{alg:put}
\begin{algorithmic}
\REQUIRE CGM $A = \{k, \{b_x, m_x\}\}$, point $p$
\STATE $c \leftarrow \text{RasterProjection}(p)$
\STATE $h_1, h_2 \leftarrow \hashfn(c)$
\FOR{$i = 0$ \TO $k-1$}
  \FOR{$x = 1$ \TO $\Lambda$}
    \STATE $j \leftarrow (h_1 + (i+1) \cdot h_2) \mod m_x$
    \STATE $v \leftarrow \val(j, L_{A,x})$
    \IF{$v < 2^{b_x} - 1$}
      \STATE $\val(j, L_{A,x}) \leftarrow v + 1$
      \STATE \textbf{break}
    \ENDIF
  \ENDFOR
\ENDFOR
\end{algorithmic}
\end{algorithm}

% GET Operation description
% - Returns minimum count across all k hash positions
% - Sums values across layers when overflow detected

\begin{algorithm}[ht]
\caption{GET Operation}
\label{alg:get}
\begin{algorithmic}
\REQUIRE CGM $A = \{k, \{b_x, m_x\}\}$, point $p$
\ENSURE $v_{min}$
\STATE $c \leftarrow \text{RasterProjection}(p)$
\STATE $h_1, h_2 \leftarrow \hashfn(c)$
\STATE $v_{min} \leftarrow \infty$
\FOR{$i = 0$ \TO $k-1$}
  \STATE $s \leftarrow 0$
  \FOR{$x = 1$ \TO $\Lambda$}
    \STATE $j \leftarrow (h_1 + (i+1) \cdot h_2) \mod m_x$
    \STATE $v \leftarrow \val(j, L_{A,x})$
    \STATE $s \leftarrow s + v$
    \IF{$v = 0$}
      \RETURN $0$
    \ENDIF
    \IF{$v < 2^{b_x} - 1$}
      \STATE \textbf{break}
    \ENDIF
  \ENDFOR
  \STATE $v_{min} \leftarrow \min(v_{min}, s)$
\ENDFOR
\RETURN $v_{min}$
\end{algorithmic}
\end{algorithm}

\section{Evaluation}
\label{sec:evaluation}

We evaluate Counting GloBiMaps against established probabilistic counting structures: Spectral Bloom Filters with Minimal Increment (SBF-MI)~\cite{cohen2003spectral} and Count-Min Sketch (CMS)~\cite{cormode2005improved}. All experiments use Zipfian-distributed data ($\alpha=1.5$) with 10,000 unique items and 100,000 total insertions, representative of power-law spatial data.

\subsection{Hash Function Sensitivity}
\label{sec:k_sensitivity}

The number of hash functions $k$ is critical for accuracy. Figure~\ref{fig:k_sensitivity} shows throughput and mean error as $k$ varies from 1 to 32.

\begin{figure}[ht]
  \includegraphics[width=8.2cm]{figures/k_sensitivity_combined.pdf}
  \caption{K-parameter sensitivity comparison. (a) Insert throughput decreases with $k$ due to additional hash computations. (b) Mean query error rapidly approaches 0\% as $k$ increases.}
  \label{fig:k_sensitivity}
\end{figure}

Key findings:
\begin{itemize}[nosep,leftmargin=*]
  \item \textbf{CGM achieves 0\% error at $k \geq 4$}, matching SBF-MI
  \item CMS requires $k \geq 11$ for perfect accuracy on this workload
  \item At $k=8$: CGM achieves 2--3$\times$ higher throughput than SBF-MI with identical accuracy
\end{itemize}

The multi-layer architecture enables efficient handling of power-law distributions where few items have high counts while most have low counts.

\subsection{Memory Efficiency}
\label{sec:memory}

With a two-layer configuration ($L_1$: 12-bit counters at $2^{16}$ slots, $L_2$: 20-bit counters at $2^{14}$ slots), CGM uses 192~KB total memory while supporting counts up to $2^{31}$ without overflow. Comparable CMS configurations require significantly more memory for equivalent accuracy on skewed distributions.

\subsection{Point-in-Polygon Queries}
\label{sec:pip}

% Polygon error: PERR = |sum_real - sum_err| / sum_real
% Higher bit-depth in last layer reduces error
For spatial aggregation queries, polygon regions are rasterized and GET operations are summed over all interior cells. The error model predicts that errors concentrate in high-frequency bins, making CGM particularly suitable for hotspot analysis where accurate counting of frequently-visited locations is more important than rare locations.
