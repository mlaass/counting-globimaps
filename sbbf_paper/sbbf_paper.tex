\begin{abstract}
Efficient membership queries for sparse spatial data---2D raster cells and 3D voxels---are critical for geospatial analytics, remote sensing, real-time rendering, and collision detection. Traditional Bloom filters minimize collisions by destroying data locality via cryptographic hashing. However, spatial data exhibits high correlation: neighboring cells are often queried together. We propose the Spatial-Blocked Bloom Filter (SBBF), which utilizes Space-Filling Curves (SFCs) to map multi-dimensional coordinates to a blocked Bloom filter structure. By using bit-splitting to derive block indices from low-order SFC bits and bit-masks from high-order bits, SBBF achieves superior cache locality and enables hardware prefetching during raster scans and volume traversals. Furthermore, we introduce Topological Verification, a spatial denoising technique that leverages the deterministic nature of SBBF collisions to filter false positives. Our preliminary analysis suggests significant throughput improvements over standard blocked filters for sequential spatial queries in both 2D and 3D applications.
\end{abstract}

\begin{IEEEkeywords}
Bloom filter, space-filling curves, raster data, voxel data, point clouds, cache optimization, spatial indexing.
\end{IEEEkeywords}

\section{Introduction}
Spatial data structures underpin applications ranging from geospatial analytics and remote sensing to computer graphics and robotics. In 2D, raster representations encode satellite imagery, land cover classifications, and digital elevation models. In 3D, voxel-based representations have seen a resurgence driven by neural radiance fields (NeRFs), sparse voxel octrees (SVOs), and large-scale point cloud processing. A fundamental operation across these domains is the membership query: \textit{Does a spatial element exist at coordinate $\mathbf{p} = (x, y)$ or $(x, y, z)$?}

Standard Bloom filters offer $O(1)$ query time and compact memory usage but suffer from poor cache performance due to the random access patterns inherent in uniform hashing. Bloom filters have been successfully applied to compress raster and voxel datasets, including global-scale spatial data~\citep{Werner2019,Werner2021}. Blocked Bloom filters (BBFs)~\citep{Putze2009} improve cache performance by confining bits to a single cache line.

In this paper, we argue that spatial locality is a feature that should be preserved. We introduce the Spatial-Blocked Bloom Filter (SBBF), which aligns the memory layout of the filter with the spatial structure of the data using Space-Filling Curves (SFCs). SFCs linearize multi-dimensional data while preserving proximity~\citep{Morton1966}, and work identically for 2D and 3D coordinates.
We use Morton (Z-order) and Hilbert curves as SFCs and show that not only can we improve cache performance but at the same time we get multiple benefits: faster indexing (replacing hash functions with bit-interleaving), lower False Positive Rates (FPR), and faster neighborhood queries. As part of this work, we contribute high-performance implementations of 2D and 3D Morton and Hilbert curve encoders that are orders of magnitude faster than state-of-the-art hash functions such as MurmurHash or XXHash.

\section{Related Work}
\subsection{Blocked Bloom Filters}
\citet{Putze2009} introduced blocked Bloom filters (BBFs) to address cache inefficiency. Standard Bloom filters require $k$ random memory accesses per query, causing up to $k$ cache misses. BBFs partition the bit array into cache-line-sized blocks (typically 512 bits). The first hash function selects a block, and the remaining $k-1$ hashes probe within that block, reducing cache misses from $k$ to 1. The false-positive rate increases slightly due to non-uniform block occupancy, modeled as a Poisson distribution, but this is compensated by 3--4$\times$ speedups.

\citet{Lang2019} further optimized BBFs with register-blocked and cache-sectorized variants. Register-blocked filters reduce block size to 32 or 64 bits (CPU register width), enabling all $k$ bits to be tested in a single comparison instruction---achieving 1--2 cycles per lookup. Cache-sectorized filters spread bits across cache-line sectors while maintaining sequential access, reducing false-positive overhead by up to 48\%. Their SIMD implementations (AVX2/AVX-512) achieve 4--10$\times$ additional speedups. However, both approaches treat spatial data as uniformly random---they optimize \emph{intra-query} cache behavior but ignore \emph{inter-query} locality for sequential spatial traversals.

\subsection{Succinct Spatial Filters}
In the database community, structures like SuRF (Succinct Range Filter) and Rosetta have been proposed for range queries. While highly efficient for prefix-matching, they often require more complex tree-like structures that are slower than the bitwise operations of Bloom filters. SBBF fills the gap between the speed of Bloom filters and the locality of spatial indices.


\subsection{Space-Filling Curves for Spatial Data}
Space-filling curves (SFCs) provide continuous mappings from multi-dimensional coordinates to one-dimensional indices while preserving spatial locality. The oldest SFC is the Morton curve~\citep{Morton1966}, which interleaves coordinate bits in round-robin fashion. Hilbert curves provide superior locality at slightly higher computational cost. Hilbert curves have a \emph{Space-to-Linear Ratio} of 6, meaning adjacent 1D positions are at most 6 units apart in the original space, with zero ``jump segments'' where consecutive indices are spatially distant~\citep{Chen2022Hilbert}. Both Morton and Hilbert curves generalize naturally to any dimension $d \geq 2$.

In spatial databases, Hilbert indexing achieves 90--95\% speedups for nearest-neighbor queries and 32--58\% for range queries compared to standard approaches~\citep{Ujang2014}. For array layouts, generalized Morton orderings can yield up to 10$\times$ speedups by aligning memory access patterns with cache hierarchies~\citep{Swatman2024}. SFCs are also used for octree indexing and point cloud compression~\citep{Chen2022}.

SBBF is the first to integrate SFCs directly into the indexing logic of a probabilistic membership structure to the best of our knowledge, using the curve not only to preserve locality but also to derive both block indices and intra-block bit patterns from a single SFC computation.

\subsection{Spatial Data Representations}
Exact spatial representations present a memory-accuracy trade-off that depends on data sparsity. \textbf{Dense voxel grids} allocate one bit per cell in an $N^d$ array, providing $O(1)$ lookup but $O(N^d)$ memory regardless of occupancy---a limitation noted by \citet{Niessner2013} in real-time reconstruction. \textbf{Sparse voxel octrees} (SVOs)~\citep{Laine2010} address this by hierarchically subdividing space, achieving approximately 5 bytes per occupied voxel; subsequent work on SVDAGs~\citep{Kampe2013} further compresses via directed acyclic graphs. For unstructured point sets, \textbf{coordinate lists} (COO format) store explicit $(x,y,z)$ tuples, requiring 64--96 bits per point with $O(\log n)$ binary search~\citep{Saad1994}. A recent review~\citep{Nguyen2021} comprehensively compares these approaches. SBBF offers a probabilistic alternative: constant memory regardless of density, $O(1)$ queries, with bounded false positive rate---trading exactness for space efficiency on sparse spatial data.

\textbf{Efficient Hilbert Encoding.} While Hilbert curves provide superior locality, the standard bit-by-bit encoding algorithm requires $O(n)$ iterations with branch-heavy rotation operations---for 16-bit coordinates, this means 16 loop iterations with conditional state transitions, yielding approximately 75~ns per encode. Recent work has addressed this via lookup table (LUT) approaches: processing multiple bits per iteration reduces the iteration count while precomputing state transitions eliminates branch mispredictions. The \texttt{fast-hilbert} library~\citep{FastHilbert} demonstrates 4-bit chunked encoding achieving 3~ns latency. For 3D, Morton-Hilbert decomposition transforms Morton codes (computed in $O(1)$ via PDEP) through a compact 96-byte LUT~\citep{ThreadLocalMutex3D}.

\subsection{Hash Functions for Bloom Filters}
Traditional Bloom filters require $k$ hash functions that satisfy uniformity and independence properties. \citet{Kirsch2008} proved that $k$ hash functions can be simulated using only two base functions via double hashing:
\begin{equation}
    g_i(x) = h_1(x) + i \cdot h_2(x) \mod m, \quad i \in \{0, \ldots, k-1\}
\end{equation}
This reduces computational overhead from $O(k)$ hash evaluations to $O(1)$.

For spatial Bloom filters, hash function performance depends critically on input size. Modern hash functions like XXH3~\citep{Collet2016xxHash} achieve 30--60~GB/s on large inputs ($\sim$100~KB), but spatial coordinates are small (16--32 bytes for 2D/3D points). On such inputs, function call overhead dominates, reducing effective throughput significantly. SBBF exploits this by replacing cryptographic hashing with space-filling curve encoding, which requires only bit-interleaving operations. Section~\ref{sec:indexing-performance} provides detailed performance comparisons.

\subsection{Spatial Mapping and Bit-Splitting}
The core of SBBF is the mapping function that converts a spatial coordinate $\mathbf{p}$ into a block index and a bit mask seed. Given an SFC value $s = \text{SFC}(\mathbf{p})$, we partition $s$ into two components:
\begin{equation}
    s = s_{\text{high}} \cdot 2^p + s_{\text{low}}
\end{equation}
where $p = \log_2 N$ and $N$ is the number of blocks. We use:
\begin{itemize}
    \item \textbf{Block index:} $\text{block\_idx} = s_{\text{low}} = s \bmod 2^p$
    \item \textbf{Bit mask seed:} $\text{seed} = s_{\text{high}} \oplus s_{\text{low}}$
\end{itemize}

\textbf{Why low bits for block index?} The low-order bits of an SFC change with every unit step in the coordinate space. Spatial neighbors map to blocks $B_i, B_{i+1}, \ldots$, enabling the CPU to leverage L1/L2 prefetching during neighborhood queries and raster/volume traversals.

\textbf{Why combine high and low bits?} Using only the high bits ($s_{\text{high}}$) as the seed causes false positives to appear as topologically coherent partial ``copies'' of the original data, since coarse spatial regions share identical seeds. We evaluate two combination strategies: XOR ($s_H \oplus s_L$) and multiply-shift ($s \cdot \phi \gg b$). XOR provides simpler implementation and lower FPR on uniformly distributed data, while multiply-shift's superior avalanche properties create more spatially incoherent false positives that are better filtered by topological verification (Section~\ref{sec:seed-strategy}).



\subsection{Intra-Block Hashing}
Once block $B_i$ is selected, we must determine which $k$ bits to set within that block. Standard Bloom filters would invoke $k$ independent hash functions, but this is computationally expensive. Following \citet{Kirsch2008}, we use double-hashing to generate $k$ positions from the seed value $\text{seed} = s_H \oplus s_L$:
\begin{align}
    h_1 &= \text{seed} \bmod B \\
    h_2 &= \lfloor \text{seed} / B \rfloor \bmod B, \quad h_2 = 1 \text{ if } h_2 = 0 \\
    \text{bit}_i &= (h_1 + i \cdot h_2) \bmod B, \quad i \in [1, k]
\end{align}

Here, $h_1$ provides the starting position and $h_2$ the step size. The constraint $h_2 \neq 0$ ensures all $k$ positions are distinct when $k \leq B$ and $\gcd(h_2, B) = 1$. For power-of-two block sizes ($B = 2^b$), we ensure $h_2$ is odd by setting the least significant bit.

\textbf{Alternative: Pattern Lookup.} For SIMD implementations, precomputed $k$-bit patterns can replace the double-hashing loop entirely. A table of $\Omega$ random patterns (typically $\Omega = 2^{16}$) is indexed by $\text{seed} \bmod \Omega$, yielding the bit mask in a single memory access. This trades 4~KB of table space for reduced instruction count (11 vs.\ 25 instructions per operation, see Table~\ref{tab:hash-comparison}).

\textbf{Collision behavior.} Unlike standard Bloom filters where collisions are uniformly distributed, SBBF collisions exhibit spatial structure. Two points $\mathbf{p}$ and $\mathbf{q}$ collide (map to identical block and mask) when they share the same low bits (same block) and when their XOR seeds $s_H \oplus s_L$ are identical. Since the seed combines both coarse (high bits) and fine (low bits) spatial information, collisions occur between points that share structural similarity at multiple scales---a property we exploit for topological verification in Section~\ref{sec:denoising}.

\subsection{Efficient SFC Encoding}

SBBF performance depends critically on fast SFC encoding. We implement LUT-based optimizations for both 2D and 3D Hilbert curves.

\textbf{2D Hilbert: Chunked LUT.} The 2D Hilbert curve can be modeled as a 4-state machine where each state represents a curve orientation. Rather than processing one bit at a time, we process 4-bit nibbles, reducing iterations from 16 to 4 for 16-bit coordinates. The LUT structure is:
\begin{itemize}
    \item \textbf{Size:} $4 \times 16 \times 16 = 1024$ entries $\times$ 16 bits = 2~KB
    \item \textbf{Index:} $(\text{state} \ll 8) \,|\, (x_4 \ll 4) \,|\, y_4$
    \item \textbf{Entry:} 8-bit Hilbert code chunk (bits 0--7), 2-bit next state (bits 8--9)
\end{itemize}

The encoding loop extracts 4-bit nibbles from coordinates, looks up the corresponding chunk and state transition, and accumulates the result:
\begin{align}
    \text{code} &= (\text{code} \ll 8) \,|\, (\text{LUT}[\text{idx}] \land \text{0xFF}) \\
    \text{state} &= (\text{LUT}[\text{idx}] \gg 8) \land \text{0x3}
\end{align}

In our experiments, this achieves ${\sim}12$ cycles per encode (Table~\ref{tab:hash-comparison}), a 25$\times$ speedup over the reference implementation while fitting entirely in L1 cache.

\textbf{3D Hilbert: Morton-Hilbert Decomposition.} Direct 3D LUT encoding would require prohibitive table sizes. Instead, we decompose the problem:
\begin{enumerate}
    \item \textbf{Morton encode:} $(x, y, z) \rightarrow$ Morton code via bit-interleaving (${\sim}3$ cycles with BMI2 PDEP)
    \item \textbf{Transform:} Morton code $\rightarrow$ Hilbert code via 96-byte LUT
\end{enumerate}

The transform LUT exploits the A4 alternating group structure of 3D Hilbert curves, which has 12 distinct states. Each 3-bit octant of the Morton code indexes into the LUT to produce the corresponding Hilbert octant and next state. In our experiments, this decomposition achieves ${\sim}24$ cycles per encode (14$\times$ speedup) while requiring only 96 bytes of table space.


\begin{algorithm}[!ht]
\caption{SBBF Core Operations}\label{alg:sbbf}
\SetKwFunction{FGetLoc}{GetLocation}
\SetKwFunction{FInsert}{Insert}
\SetKwFunction{FQuery}{Query}
\SetKwFunction{FSFC}{SFCEncode}
\SetKwProg{Fn}{Function}{:}{}
\Fn{\FGetLoc{$s$}}{
    $s_L \gets s \bmod 2^p$\tcp*{Low bits: block index}
    $s_H \gets \lfloor s / 2^p \rfloor$\tcp*{High bits}
    $\textit{seed} \gets s_H \oplus s_L$\tcp*{XOR for better distribution}
    $h_1 \gets \textit{seed} \bmod B$;
    $h_2 \gets \lfloor \textit{seed} / B \rfloor \bmod B$;
    \lIf{$h_2 = 0$}{$h_2 \gets 1$}
    $\textit{mask} \gets 0$\;
    \For{$i \gets 1$ \KwTo $k$}{
        $\textit{mask} \gets \textit{mask} \lor (1 \ll ((h_1 + i \cdot h_2) \bmod B))$\;
    }
    \Return $(s_L, \textit{mask})$\;
}
\Fn{\FInsert{$\mathbf{p}$}}{
    $s \gets \FSFC(\mathbf{p})$;
    $(\textit{idx}, \textit{mask}) \gets \FGetLoc(s)$\;
    $\textit{blocks}[\textit{idx}] \gets \textit{blocks}[\textit{idx}] \lor \textit{mask}$\;
}
\Fn{\FQuery{$\mathbf{p}$}}{
    $s \gets \FSFC(\mathbf{p})$\;
    $(\textit{idx}, \textit{mask}) \gets \FGetLoc(s)$\;
    \Return $(\textit{blocks}[\textit{idx}] \land \textit{mask}) = \textit{mask}$\;
}
\end{algorithm}

As illustrated in Fig.~\ref{fig:tv-concept}, SBBF collisions on structured data (like surfaces) often manifest as "speckle" noise. Because real voxel data is connected, we can filter queries that lack spatial neighbors.

Because SBBF mapping is deterministic and spatially coherent, false positives (FPs) appear as regional noise rather than isolated random bits. We implement a "Consensus" query:
\begin{equation}
    Query_{TV}(V) = Query(V) \land (CountNeighbors(V) \ge \tau)
\end{equation}
where $\tau$ is a connectivity threshold. The experiments in Fig.~\ref{fig:tv-concept} use $\tau = 2$ (26-connected neighborhood), $k = 4$ hash functions, $2^{15}$ blocks of 64 bits each, and Hilbert 3D space-filling curve indexing. This allows SBBF to operate at higher theoretical False Positive Rates (FPR) than standard BFs while maintaining effective precision.



\section{Experiments}

\subsection{Experimental Setup}
All benchmarks were conducted on a Linux workstation with an Intel Core i7-9700K (8 cores, 3.6~GHz base, 4.9~GHz turbo) and 32~GB DDR4-3200 RAM. Code was compiled with GCC 12.2 using \texttt{-O3 -march=native}. We use the nanobench library~\citep{nanobench} with Linux \texttt{perf\_event} for cycle-accurate measurements.

\textbf{Datasets.} We evaluate on the GDELT Global Event Database containing 1.93M georeferenced news events. For 2D experiments, coordinates are quantized to 16-bit precision. For 3D experiments, we include an event category dimension (QuadClass: verbal/material cooperation/conflict).

\textbf{Baselines.} We compare SBBF against two cache-optimized Bloom filter variants:
\begin{itemize}
    \item \textbf{BlockedBF}~\citep{Putze2009}: 512-bit cache-line-aligned blocks
    \item \textbf{RegisterBF}~\citep{Lang2019}: 64-bit register-blocked design
\end{itemize}
All filters use identical memory budgets (1.05~MB) for fair comparison.

\subsection{Random Access vs.\ Linear Traversal}
The primary advantage of SBBF is revealed during linear spatial scans. Figure~\ref{fig:l1dcache} shows L1-dcache miss rates during volume traversals across grid sizes from $64^3$ to $256^3$ voxels. SBBF with sequential SFC iteration maintains near-zero miss rates (0.05--0.15\%) regardless of grid size, as the sequential block access pattern enables effective hardware prefetching. In contrast, hash-based filters exhibit substantially higher miss rates that increase with data size: at $256^3$, Standard Bloom Filter reaches 7.9\%, BlockedBF 3.7\%, and RegisterBF 2.0\%. This 40--160$\times$ difference in cache efficiency demonstrates that SBBF's SFC-based block indexing transforms random memory access patterns into sequential scans, fundamentally changing the cache behavior from capacity-limited to prefetcher-optimized.

\subsection{Seed Strategy Comparison}\label{sec:seed-strategy}
The seed derivation strategy determines how the SFC code is transformed into the intra-block hash seed. We evaluate two strategies:

\textbf{XOR Strategy.} The seed is computed as $\text{seed} = s_H \oplus s_L$, combining the high-order bits (regional signature) with low-order bits (local position) via bitwise XOR. This approach requires no additional constants and provides direct bit mixing.

\textbf{Multiply-Shift Strategy.} The seed is computed as $\text{seed} = (s \cdot \phi) \gg b$, where $\phi = 2654435769$ (the golden ratio prime). Multiplicative hashing provides superior avalanche properties but requires a multiplication instruction.

We conduct a comprehensive evaluation across six dataset types: uniform synthetic (2D/3D), clustered synthetic (2D/3D with 50 Gaussian clusters, $\sigma=500$), real-world geographic (GDELT 1.9M events), and voxelized 3D meshes. Figure~\ref{fig:seed-strategy} summarizes the results.

\textbf{Key Findings.} The optimal seed strategy depends strongly on data distribution:

\begin{itemize}
    \item \textbf{Uniform synthetic data:} XOR achieves marginally lower FPR ($\sim$1.9\% vs.\ $\sim$2.0\%) across all SFC and intra-block combinations. The differences are small ($<$5\% relative).

    \item \textbf{Clustered synthetic data:} Results are mixed. Multiply-shift often outperforms XOR, particularly with Hilbert SFC and \texttt{pattern\_lookup} (2.09\% vs.\ 2.21\% in 2D). The clustering appears to favor multiply-shift's avalanche properties.

    \item \textbf{GDELT geographic data:} XOR dramatically outperforms multiply-shift by 5--11$\times$ (0.002--0.008\% vs.\ 0.019--0.057\%). Real-world geographic data exhibits strong spatial structure that XOR's direct bit-mixing handles better than multiply-shift's uniform scrambling.

    \item \textbf{Voxelized meshes:} The intra-block strategy determines the winner. With \texttt{double\_hash}, multiply-shift achieves 1.5--2$\times$ lower FPR. With \texttt{pattern\_lookup}, XOR achieves 2--3$\times$ lower FPR. This interaction suggests the bit patterns from each strategy align differently with the two hashing methods.
\end{itemize}

For voxelized meshes with topological verification and \texttt{double\_hash}, multiply-shift excels. For uniform or clustered synthetic data, either strategy performs comparably. When using \texttt{pattern\_lookup} on voxels, prefer XOR.

\subsection{Hash Function Count Sensitivity}\label{sec:k-sensitivity}
The number of hash functions $k$ directly affects both FPR and computational cost. Standard Bloom filter theory establishes the optimal $k = \ln(2) \cdot (m/n)$ for minimum FPR at 50\% fill rate~\citep{Kirsch2008}. Prior work on cache-efficient filters recommends $k \in \{6, 8\}$ as the practical sweet spot, noting that $k > 11$ is never performance-optimal~\citep{Lang2019}, while SIMD-optimized variants prefer $k$ as a power of two for cache-line alignment~\citep{Putze2009}. We evaluate $k \in \{2, \ldots, 12\}$ while maintaining constant 50\% fill rate by adjusting filter size ($m = 2nk$).

\textbf{Key Findings.} FPR decreases rapidly from $k=2$ ($\sim$10\%) to $k=6$ ($\sim$0.5\%) across all data types, consistent with the theoretical optimum $k \approx 0.693 \cdot c$ where $c$ is bits per element. Beyond $k=6$, synthetic data shows diminishing returns---matching prior findings~\citep{Lang2019}---while voxelized meshes continue improving through $k=11$. We attribute this divergence to the structured spatial locality in voxel data: SFC-indexed points cluster in memory, reducing the effective collision rate and shifting the optimum toward higher $k$. Based on these results, we use $k=8$ as the default throughout this paper unless otherwise specified, balancing FPR reduction, cache efficiency (power-of-two alignment), and computational cost.

\section{Discussion}
SBBF represents a paradigm shift from "locality-destroying" hashing to "locality-preserving" indexing. The choice of SFC presents a trade-off: **Morton** is optimal for high-speed streaming due to its $O(1)$ hardware encoding, while **Hilbert** is superior for complex neighborhood queries where its $Space-to-Linear$ ratio of 6 vs.\ 9 for Morton, yields higher cache hit rates during sequential spatial scans. For neighborhood-heavy applications like voxel processing, Hilbert's locality advantage outweighs its encoding cost.

\textbf{Seed Strategy.} The choice between XOR and multiply-shift depends on data distribution and application. XOR dramatically outperforms on real-world geographic data (5--11$\times$ lower FPR on GDELT) and performs marginally better on uniform synthetic data. Multiply-shift excels on voxelized meshes with \texttt{double\_hash} and topological verification, achieving near-zero FPR after denoising. Interestingly, the intra-block strategy interacts with seed choice: \texttt{pattern\_lookup} favors XOR while \texttt{double\_hash} favors multiply-shift on structured 3D data.

\textbf{When to use SBBF.} SBBF has better performance than standard bloom filters even with state-of-the-art hash functions and is most advantageous for: (1) sequential spatial traversals (raster scans, volume rendering), (2) neighborhood-intensive queries (morphological operations, connectivity analysis), and (3) applications tolerant of topological verification overhead.

\textbf{Limitations.} SBBF assumes spatial coherence in the data; randomly distributed points gain less benefit. The SFC encoding is comparable to fast hashing for single queries, though this is amortized over spatial batches. Topological verification adds latency but improves precision for structured data.

\section{Conclusion}
We presented SBBF, a spatial-blocked Bloom filter that aligns memory layout with spatial structure via space-filling curves. SBBF achieves 5--7$\times$ fewer instructions than cache-optimized baselines while providing 3--6$\times$ lower false positive rates. Our high-performance SFC encoders (2D/3D Morton and Hilbert) are orders of magnitude faster than standard hash functions. Combined with topological verification, SBBF achieves near-zero effective FPR on structured spatial data. Future work will explore SBBF for distributed spatial indexing and large-scale 3D data processing.
